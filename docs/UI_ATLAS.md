# Career Quest interface inventory

The atlas release keeps the server as the authority for available identities, scoped data, and mutations. The client has eight screens. The table records their main action and the states shown to the user; a missing server permission remains a server error.

| Screen                 | Roles                        | Main action                                                                                                                              | Other states                                                                                                                   |
| ---------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| My path                | Employee                     | Review all skills and target requirements, required assignments, four visible recommendation factors, ordered roadmap steps, full filtered history, preview and submit evidence | No goal, no assignment, no candidate, AI fallback/unavailable, stale recommendation refresh, pending advisor review, confirmed server result, route search limit |
| Practical projects     | All five, with scoped queues | Employee submits or revises; advisor approves/revises/rejects and accepts evidence; manager decides resources; supervisor decides policy | Queue by status, selected detail, pending criteria, evidence, decision history, empty queue                                    |
| People and assignments | Advisor, manager, HR         | Search/select employee and inspect skills, history, and route; manager/HR assign; advisor confirms completion and sees actual skill, coverage, route, and XP delta | Empty search, pending result/help, reason dialog, scoped profile loading/error |
| Analytics and import   | HR                           | Inspect employee-skill coverage and mandatory/voluntary participation, drill through blockers to a selected employee, preview and apply import | Empty denominators, file replacement/removal, invalid preview, row errors, warnings; import opens the new employee |
| Catalog                | All roles                    | Search and inspect activity                                                                                                              | Audience, format, gains, prerequisites, dates, no results                                                                      |
| External opportunities | Employee                     | Search by skill and propose a found source as a practical project                                                                        | Unknown cost/duration/approval, unavailable search, empty results                                                              |
| Rewards                | Employee                     | View balance/history and request an available reward                                                                                     | Insufficient balance, empty history, ledger reasons                                                                            |
| Decisions and audit    | HR, supervisor               | Inspect dated decisions and structured details                                                                                           | Scoped empty log and technical details                                                                                         |

Desktop navigation uses the fixed sidebar. Tablet uses a menu. Phone navigation exposes three primary sections with short translated visible labels and full accessible names; “More” lists every remaining section by its full name. The desktop header shows the current identity and role once; narrow phones reserve header space for the CQ mark and controls. Role switching, simulated date, and reset live in the demo dialog. All dropdowns share one accessible styled popup; long skill and activity lists search inside it. Every screen supports RU, KK, EN through client dictionaries and stable-ID source catalog translations. Unknown imported text and user comments retain their original language.

The first interface pass selected composition B in [DESIGN.md](../DESIGN.md). The Must-have refinement keeps the same visual language and exposes the server's ordered roadmap and confirmed completion receipts. Release verification is recorded by the coordinator.

The complete skill list is scrollable and puts critical unmet target requirements first. A dash marks skills without an assessment; it does not claim a zero level. Plan progress describes the share of the original gap closed for the current goal, following `docs/FORMULAS.md`.
