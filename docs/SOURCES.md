## 2. Приоритет материала

S-TZ и S-RULES задают требования хакатона. S-FINAL фиксирует согласованный командой дизайн, который должен им соответствовать. Предыдущие обсуждения и предварительный README не заменяют финальную спецификацию.

В частности, здесь сохранены **не взвешенная** формула Coverage и точная формула Priority из S-FINAL. Ранее обсуждавшиеся альтернативные веса, стек Python и другие предварительные предложения не подменяют финальный документ.

При конфликте источник не исправляется молча. Вопрос вносится в [реестр открытых решений](15_RELEASE_AND_LIMITATIONS.md), получает владельца, решение и тест после согласования.

## 3. Статус документации и реализации

Формулировки «сервер вычисляет», «система возвращает», «advisor принимает» описывают **требуемое поведение**. Они не являются заявлением, что соответствующий обработчик уже написан.

| Обозначение | Значение |
|---|---|
| P0 | Обязательное ядро и условия допуска. |
| P1 | Согласованное продуктовое расширение команды. |
| P2 | Углубление после устойчивых P0/P1. |
| NOT_RUN | Проверка не выполнена; успех не установлен. |
| PASS | Есть воспроизводимое подтверждение для конкретного commit и окружения. |
| FAIL | Проверка выполнена, наблюдается несоответствие. |
| `null` в паспорте | Фактический параметр ещё не установлен. |
| Проектный пример | Предложение контракта, не доказательство существования файла/endpoint/команды. |

Весь набор T01–T20 первоначально имеет статус `NOT_RUN`. Проверка ссылок в Markdown не является проверкой приложения.

## 4. Чего комплект не утверждает

Не проверены текущая видимость и содержимое remote, наличие реализованного сервера, model ID и действительность ключа, цены API, достаточность бюджета, размещение judge gateway и его сроки, измеренная latency, результаты unit/E2E/clean-room тестов.

Не заявлены внедрение в банке, кадровая сертификация, рост завершаемости, экономия бюджета или гарантированное повышение сотрудника.

Локальные пути к секретам, настройки личного аккаунта разработчика и пожелания к моделям агентов разработки не нужны экспертам для запуска продукта и в документацию развёртывания не перенесены.
