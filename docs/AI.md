# AI recommendation and external search

`recommend(profile, { apiKey, model?, locale?, workspaceVersion?, timeoutMs? })` is the server-side entry point in `src/ai/index.ts`. Pass the domain-built `Profile` unchanged; the AI module never calculates eligibility, skill gains, or promotion. The server owns the API key, request authorization, rate limits, and budget. The only allowed model is `gpt-5.4-mini`; an invalid `OPENAI_MODEL` or explicit model selects the rules fallback without a provider call. The Responses request uses `reasoning: { effort: 'none' }`, a strict schema, and a 1200-token output cap.

The module sends role and grade, target, gaps, up to 12 recent history records (IDs/status/date), and up to 16 eligible voluntary catalog candidates. It also includes each candidate's domain-computed `H` index for voluntary events of the same type and format over the previous 180 days, with a candidate-specific evidence ID. This is a heuristic based on completion and non-completion statuses, not a probability. Exact aggregate counts cannot be reconstructed from `Profile` because it has history event IDs but no full historical event catalog; the domain's `H` is the source of truth. It does not send the employee name, department, manager, or the whole organization. It asks the model to choose and compare 1–3 candidates using a strict JSON schema. It validates unique eligible event IDs, three or more distinct factor groups, known evidence IDs covering those groups, a reference to the chosen event, and a real alternative when available. A bad or failed response becomes `rules_fallback`; no goal, fulfilled skill requirements, or no eligible candidate becomes `unavailable` with a distinct warning. Without a key it uses the same truthful fallback. The fallback is a deterministic domain-priority display, never described as live AI.

The cache contains only validated live results. Its key hashes the **entire** profile plus workspace version, locale, model, and prompt version. A changed completion, goal, credit-derived profile, catalog candidate, or policy output therefore cannot reuse old advice. Same-key concurrent calls share one provider request. The cache is process-local and capped at 200 entries. The server may add workspace version to invalidate on changes not represented in `Profile`. Cached results report `cached_live_ai` with the original `generated_at`.

`searchExternalOpportunities({ skill_id, skill_name, desired_level, language, format?, constraints? }, { apiKey?, model? })` is optional and separate from primary recommendations. It sends only skill metadata, uses the hosted `web_search` tool, and accepts a returned HTTPS URL only when it occurs in the completed search call's sources. It never fetches the URL from the application server. A found page is a proposal source, not company approval, a skill credit, or proof of cost, duration, or availability: those fields remain unknown. Without a key or a source-backed result it returns `unavailable` or an empty result and preserves the manual proposal path. The helper is not wired to an HTTP route in this branch.

Tests: `npm run typecheck` and `node_modules/.bin/tsx --test tests/ai.test.ts`. They mock the provider to test model choice, evidence validation, cache invalidation and deduplication, failure fallback, injection, and source URL filtering. No live OpenAI call or end-to-end 10-second measurement was made here; the coordinator owns the live key, budget gateway, and integration smoke test.
