# AI recommendation and external search

`recommend(profile, { apiKey, model?, locale?, workspaceVersion?, timeoutMs?, catalogEvents? })` is the server-side entry point in `src/ai/index.ts`. Pass the domain-built profile unchanged and the complete server-side `dataset.events` catalog through `catalogEvents`. The AI module does not calculate eligibility, gains, caps, or promotion. The server owns the key, authorization, rate limits, and budget. The only allowed model is `gpt-5.4-mini`; an invalid model selects the rules fallback without a provider call. The Responses request uses `reasoning: { effort: 'none' }`, a strict schema, a 1200-token output cap, and a 9.3-second default provider timeout.

Only eligible, useful, voluntary catalog candidates reach the model. For each candidate, the server includes domain-computed capped gains, target and critical contributions, prerequisite unlock count, max levels, and compact participation aggregates. History is scanned in full through `as_of`; primary relevance is overlap between skills developed by the candidate and currently open goal skills. It reports completed, dropped, no-show, and declined counts plus the latest relevant activity. Type/format counts over 180 days and the domain `H` index remain secondary heuristics, never predictions. The full catalog is essential for recognizing past events that are no longer current candidates. The model receives no employee name, manager, department, record ID, or raw personal history rows.

The model returns only 1–3 eligible event IDs, a supported priority code, the four factor keys, evidence IDs, and a real alternative ID when available. It cannot supply explanatory prose or numbers. Every candidate carries server-computed `allowed_priority_codes` and `required_evidence_ids`; a candidate-scoped strict schema limits its event ID, priority code, evidence ID vocabulary, and alternative ID to valid values. The model is instructed to copy one allowed code and the exact evidence IDs. `critical_target` requires positive critical gain; `target_gap` requires positive target gain; `prerequisite_unlock` requires a positive unlock count; `participation_fit` requires positive target gain and more related completions than all drops, no-shows, and declines combined. The validator still rejects duplicate/unknown IDs, unsupported priority, missing factors, mismatched gap evidence, missing candidate-specific history, extra fields, and nonempty model warnings. Such output becomes `rules_fallback` and is never displayed as verified live AI.

The server renders localized `summary`, `reason`, `alternative_reason`, and four `facts[]` from verified profile/candidate data. The facts show current grade, target role and grade, a concrete current/required skill gap with critical marker, and full relevant-history counts. The `summary` states the validated priority; the full `reason` also shows capped gain and unlocked activity count. `alternative_reason` compares the chosen and alternative events using verified target gain, critical gain, hours, and related-history counts; equal gains are stated as equal. Only the selected event and priority come from the model. The fallback is deterministic domain priority and is labeled `rules_fallback`; successful uncached calls are `live_ai`, and validated cache hits are `cached_live_ai`. No goal, fulfilled target, or no useful eligible candidate produces `unavailable`. Warnings and diagnostics are localized and do not expose provider errors.

The cache hashes the entire profile, catalog, workspace version, locale, model, and prompt version (`recommend-v3-verified-priority`). Concurrent identical calls deduplicate; only validated live results are cached, up to 200 process-local entries. Changed history, completion, goal, candidate, catalog, or language produces a different key. Locale is presentation-only and supports RU, KK, EN.

`searchExternalOpportunities(...)` remains optional and separate from primary recommendations. It sends bounded skill metadata, uses at most one hosted `web_search` call, and accepts HTTPS URLs only when returned by the completed search source list. It never fetches URLs from the application server. Titles/excerpts are model summaries; source URLs are checked. A found page is a proposal source, not approval, skill credit, or proof of cost, duration, or availability. Without a key or a source-backed result it remains unavailable and preserves the manual proposal path.

Run `npm run typecheck` and `node_modules/.bin/tsx --test tests/ai.test.ts` for mocked semantic tests. `npm run smoke:judge` validates a fresh imported employee and CSV history, then requires a cold live AI call below 10 seconds with 1–3 unique eligible recommendations, four factual factors, a real alternative, and correct locale. `--all-locales` checks RU, KK, EN; each result is an individual measurement, not p95. The smoke requires a reachable configured gateway or server AI key and should not be described as passed until actually run.
